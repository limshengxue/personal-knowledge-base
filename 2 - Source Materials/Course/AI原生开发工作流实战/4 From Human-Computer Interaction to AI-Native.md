# 4 From Human-Computer Interaction to AI-Native
## Integration Difficulty
- We often feel "weird" to work with AI
![[Attachments/Pasted image 20260411124909.png]]
### Level 1 : AI as External KB
- Web version : chatgpt, gemini
- No contextual knowledge of your code
- Only value if information retrieval and Q&A
- 极高的上下文摩擦力

### Level 2: AI as Copilot
- AI deeply embedded into our IDE
- Reduce context friction significantly
- still problems
	- passive - no active actions
	- limited context - document-level
	- limited action space - limited to IDE only

### Level 3: AI as Native Workflow Agent
- Claude code 
- It have better contextual info, better planning, and better interaction with shell command

### Level 4: AI as Autonomous Software Engineer
- This is the future we are heading to
- We can see some initiative like YOLO mode of Claude
- The skills we learn to adopt Level 3 helps to build the future of Level 4
- 精通 Level 3，就是在为 AI 建造一条安全、清晰的“F1 赛道”。 
- 规范（Specs）是赛道的“导航地图”，告诉 AI 终点在哪里，必须经过哪些检查点。
- 宪法（Constitution）和安全配置是赛道的“护栏”，防止 AI 冲出危险区域。 
- 自定义工具和自动化测试是赛道的“维修站”和“监控系统”，确保 AI 在遇到问题时有标准化的解决方案。 
- 触及 Level 4，就是在这条精心建造的赛道上，开启“自动驾驶模式”（即无人值守的 YOLO 模式），并信任它能够安全、高效地跑完全程。

## Inversion of Value
![[Attachments/Pasted image 20260411130539.png]]


![[Attachments/Pasted image 20260411130558.png]]
- The core values switch from coding to intent definition and specs design
- Design and workflow orchestration become important
- We only concern about the least core coding

这场“价值倒转”，正是我们开发者角色三重转变的根本原因。它不是让我们被取代，而是推动我们“向上游走”，去从事那些更贴近业务、更考验系统性思维和创造力的工作。 
1. 从代码的“生产者”到规范的“设计者”：你的核心产出，将从 .go 文件，变为那份能够生成无数正确 .go 文件的 .spec.md。 
2. 从任务的“执行者”到工作流的“指挥家”：你的核心技能，将从“如何实现一个功能”，变为“如何设计一个能让 AI 自动实现功能的流程”。 
3. 从被动的“修复者”到主动的“治理者”：你的核心价值，将从“修复一个 Bug”，变为“设计一个能让 AI 在开发阶段就避免这类 Bug 的质量体系”，并成为 AI 所有高风险操作的最终“审批人”
